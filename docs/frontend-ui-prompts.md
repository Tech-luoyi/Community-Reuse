# 邻里流转 · 前端页面生成提示词

> 用途：按阶段把页面交给 AI 生成或重构时，直接复制对应提示词。
> 前置：先阅读 `docs/frontend-design-system.md` 和 `docs/api-contract.md`。

## 1. 全局基础提示词

```text
你是一个资深前端设计师和 Next.js 工程师，请为“邻里流转”设计并实现高质量 Web UI。

产品定位：
面向小区、楼栋或办公室内部的闲置物品流转工具，不是电商平台，也不是后台管理系统。目标是让用户快速看到仍然可领取的物品，并完成领取申请、预约、交接和归档。

整体风格：
- 社区信任感 + 精品市集 + 轻 AI 助手
- 通透、克制、温暖、专业、轻盈、可信
- 高级感来自留白、排版、组件质感、状态清晰，而不是复杂动画
- PC 优先，移动端响应式适配

技术要求：
- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- shadcn/ui
- Lucide icons
- React Hook Form + Zod
- 不使用深色科技风，不使用电商大促风，不使用后台管理模板风

设计 token：
- 页面背景：#F7F7F2
- 卡片背景：#FFFFFF
- 主色：#10B981
- 强调色：#F59E0B
- AI 功能色：#8B5CF6
- 文本主色：#17211C
- 文本次级：#667085
- 边框：#E7ECE9
- 可领取：绿色
- 已预约：蓝紫
- 已送出/归档：灰色
- 拒绝/危险：#EF4444
- 卡片圆角：16px
- 按钮圆角：10-12px
- 徽章圆角：999px
- 阴影轻微、柔和，hover 时增强

页面要求：
- 顶部导航包含产品标识、当前空间、搜索、发布按钮、通知和用户菜单
- 所有列表、详情、表单都要有空状态、加载骨架和错误状态
- 所有写操作完成后使用 Toast 反馈
- 状态不仅用颜色，也必须有文字
- 中文界面，文案真诚、清楚、社区感
- 不使用图片文字、大渐变海报、玻璃拟态和花哨动画

请根据以上要求生成页面结构、组件拆分和核心样式。组件必须真实可落地，不要只做视觉稿。
```

## 2. 加入空间 `/join`

```text
为“邻里流转”生成加入空间页面 `/join`。

页面目标：
用户输入邀请码和昵称后加入一个小区、楼栋或办公室流转空间。

必须包含：
- 品牌区：邻里流转 + slogan“让闲置，在沉没前被看到。”
- 邀请码输入框
- 昵称输入框
- 提交按钮
- 邀请码错误的错误状态
- 提交中的 loading 状态
- 私密空间说明：仅当前空间成员可以浏览和申请
- 移动端单列布局

视觉：
不要太像登录页，要像进入一个可信的邻里空间。留白充分，背景可以使用极轻的绿色和琥珀色光晕。
```

## 3. 首页 `/`

```text
基于全局设计系统，为“邻里流转”生成首页。

页面目标：
用户打开后能立刻看到当前社区仍然可领取的物品，并能快速搜索、筛选、收藏和进入详情。

必须包含：
- 顶部导航
- 当前空间信息
- slogan：“让闲置，在沉没前被看到。”
- 搜索框
- 胶囊筛选器：分类、交易方式、新鲜度、排序
- 响应式物品卡片流
- 新鲜度徽章
- 可领取 / 已预约 / 已送出状态
- 收藏按钮
- 空状态
- 错误状态
- 骨架屏
- 移动端筛选 Sheet 或折叠面板

重点：
高级感来自卡片层次、留白、图片比例、信息密度和状态清晰，不要添加无关 hero 大 banner。
```

## 4. 发布页 `/items/new`

```text
为“邻里流转”生成发布物品页 `/items/new`。

页面目标：
帮助用户快速发布一件真实可领取的闲置物品，并提供 AI 定价与 AI 润色辅助。

必须包含：
- 左侧发布表单：名称、分类、描述、交易方式、价格、图片上传
- 图片上传组件支持预览、删除、排序、最多 6 张
- 右侧 AI 助手区：AI 定价建议、AI 描述润色建议
- AI 建议卡支持一键采用和重新生成
- 发布前检查清单
- 表单实时校验
- 提交中状态
- 成功反馈并跳转详情

重点：
AI 是辅助，不要遮挡主流程。页面要像一个发布工作台，而不是普通表单。
```

## 5. 物品详情页 `/items/[id]`

```text
为“邻里流转”生成物品详情页。

页面目标：
让用户快速判断物品是否仍可领取，并可以收藏、留言、提交领取申请；发布者可以管理申请和完成交接。

必须包含：
- 左侧图片画廊
- 右侧物品信息卡：名称、交易方式、价格、分类、新鲜度、发布者、发布时间
- 状态展示：可领取、已预约、已送出
- 收藏按钮
- 我要领取按钮
- 领取申请表单：备注、期望时间、期望地点
- 发布者申请管理面板：接受、拒绝、完成交接
- 联系方式只在申请被接受后展示，否则显示隐私提示
- 公开留言板
- AI FAQ 回复助手
- 已归档只读状态
- 加载、错误、无留言空状态

重点：
操作状态必须非常清楚，用户不能误解物品是否还在。
```

## 6. 我的申请 `/requests`

```text
为“邻里流转”生成我的申请页面。

页面目标：
申请人查看自己发出的申请；发布者查看别人对自己物品发起的申请，并进行接受、拒绝和完成操作。

必须包含：
- Tabs：我发起的 / 我收到的
- 申请卡片或表格
- 物品缩略信息
- 申请人昵称
- 留言
- 期望时间
- 期望地点
- 状态徽章
- 按状态出现的操作按钮
- 空状态
- 加载骨架
- 接受、拒绝、完成后的 Toast

重点：
不要做成后台表格风。要像一套清晰的邻里交接记录。
```

## 7. 通知中心 `/notifications`

```text
为“邻里流转”生成通知中心。

必须包含：
- 未读和全部筛选
- 通知列表
- 申请、接受、拒绝、完成、归档的图标区分
```

## 8. 数据看板 `/dashboard`

```text
为“邻里流转”生成数据看板。

页面目标：
像社区运营周报，让用户快速了解本月发布、成交、在售和受欢迎物品。

必须包含：
- 本月发布
- 本月成交
- 当前在售
- 最快被领走
- 最想要
- 数字卡片
- 精选物品卡片
- 空状态

视觉：
不要做成后台管理系统。用大数字、清楚说明和少量精选卡片体现信息密度。
```

## 9. 组件生成提示词

### ItemCard

```text
为“邻里流转”生成 ItemCard 组件。

要求：
- 图片比例固定 4:3
- 新鲜度徽章叠在图片左上角
- 收藏按钮叠在图片右上角
- 标题最多两行
- 交易方式和价格清楚展示
- 描述最多两行
- 发布者和发布时间
- 申请数、收藏数
- hover 上浮 2px，阴影增强
- 点击进入详情
- 不使用过多圆角和强渐变
```

### StatusBadge

```text
生成 StatusBadge 组件，统一展示：
刚上架、新上架、已上架 N 天、可领取、已预约、已送出、待处理、已接受、已拒绝、已取消、已完成。

要求：
- 颜色统一由设计 token 控制
- 必须有文字，不只用颜色
- 圆角 999px
- 尺寸紧凑，适合卡片和详情页
- 支持 icon 可选
```

### EmptyState

```text
生成 EmptyState 组件。

要求：
- 支持图标或轻量插画
- 一句清楚说明
- 可选主按钮和次按钮
- 用于无物品、无申请、无留言、无通知
- 文案友好但不过度卖萌
```

### ClaimPanel

```text
生成 ClaimPanel 组件。

要求：
- 展示物品当前状态
- 可领取时显示“我要领取”
- 提交申请表单包含备注、期望时间、期望地点
- 已预约时显示交接信息
- 发布者视角显示申请列表和接受、拒绝、完成按钮
- 联系方式只在申请被接受后展示
- 所有操作都有 loading 和 Toast
```

### PricingAssistant / PolishAssistant / FaqAssistant

```text
为“邻里流转”生成 AI 助手组件。

要求：
- 浅紫色描边或极浅紫背景，不使用炫酷赛博风
- 显示“智能建议”标签
- 有生成中、成功、降级和错误状态
- 支持采用建议和重新生成
- 降级时显示“离线建议”灰标和 Tooltip
- AI 内容是辅助，不遮挡表单主流程
```
