# 需求原文（来源：腾讯文档 AICoding实战考试）

AI Coding实战考试
考试说明
考试时间： 24小时内完成
提交内容： 5分钟视频（Demo + 讲解）+ 数据库ER图 + 技术栈简介
开发要求： 必须使用AI Coding工具（Cursor/Claude Code等）辅助完成
技术栈不限： 前后端、数据库可自由选择（但必须是“全栈”）
访问方式： 本地运行即可，部署到远端可访问是加分项
设备不限： PC端或移动端均可，根据场景自行判断最优形态
场景与痛点
你刚搬到一个新城市，发现小区里有很多闲置物品在业主群里流转：婴儿车、电磁炉、书籍、绿植……但微信群的消息刷得太快，东西还没被人看到就沉了。你想用掉的东西不知道怎么定价，想买的人不知道东西还在不在。更麻烦的是，交易双方要私聊约时间、约地点，经常鸽来鸽去。
你隐约觉得，一个轻量级的、专门给小区/楼栋/办公室内部用的闲置流转工具——不需要复杂的信用体系，因为都是熟人；不需要快递，因为就在隔壁楼；最重要的是，让闲置物品在沉没之前被看到。
功能要求（可任意取舍）
1. 物品发布
发布闲置物品：名称、描述、期望交易方式（免费送/随便给/标价）、物品状态图片（可用占位图或上传功能）
每件物品有"新鲜度"标识：发布24小时内为"刚上架"，72小时内为"新上架"，之后为"已上架X天"
发布者可标记物品为"已送出"，物品进入归档状态但保留记录
2. 物品浏览与检索
以卡片流形式展示当前可领取/购买的物品，按新鲜度排序（越新越靠前）
支持按交易方式筛选（只看免费的/只看标价的）
支持关键词搜索（名称、描述）
已归档的物品可查看但不可操作
3. 意向表达与沟通
浏览者可以对物品表达"想要"，发布者能看到有谁想要
双方确认交易后，发布者将物品标记为"已送出"，系统自动记录交易完成
简单的留言板功能：围绕每件物品可公开留言问答（如"还在吗？"“几成新？”），避免重复私聊
4. 数据看板
展示当前社区/小区的活跃数据：本月发布数、本月成交数、当前在售数
展示"最快被领走的物品"（从发布到标记已送出的时间最短）
展示"最想要的物品"（被最多人点击"想要"但未成交的）
5. 使用LLM API
智能定价建议： 用户输入物品名称和简单描述，调用LLM API返回建议定价区间或"建议免费送"的判断
物品描述优化： 用户输入粗糙的描述，LLM帮助润色成更吸引人的转让文案
交易FAQ自动回复： 针对常见提问（“还在吗？”“能否自提？”“能否刀？”），LLM根据物品信息自动生成回复建议
考察重点
AI Coding实战：借助AI工具完成全栈开发（前端界面+后端API+数据库），而非手动搭建每一层
全栈工程：数据库设计是否合理、前后端是否解耦
快速决策：24小时内对功能取舍、技术选型、UI取舍的决断能力
对大模型的熟悉：能够在产品中实现简单的LLM相关能力
用户体验：功能不求完整，但UX须顺滑；前端UI设计不必完美，但须体现你的“审美水准”和“动手能力”
我们不看完美，只看你的潜力+借助AI的能力，能否把想法快速变成解决实际痛点、可运行、拿得出手的东西。
